🚀 5-Minute Quickstart

Just want to get started? Here's the bare minimum:

  1. Enable Auto-inject Panel (Optional): Go to Extensions → WebWire → Options (or click the ⚙️ Go to Options button above) and check the "Auto-inject Panel" checkbox. This isn't required - from any page you can click in the navigation bar on Extensions, select the WebWire extension, and toggle the selector at the bottom right of the popup to enable the assistant on any site.
  2. Go to the WebWire Options page.
  3. Scroll to Provider Settings and find your preferred service (e.g., OpenAI, Anthropic).
  4. Paste your API Key into the correct field.
  5. Scroll up to Model Configuration. Under Chat Model (Primary):
    • Enter the Model Name (e.g., gpt-4.1, claude-sonnet-4-20250514, gemini-2.5-flash).
    • Select the correct Provider from the dropdown.
  6. Click 💾 Save All Settings.
⚠️ Important: Always remember to click the 💾 Save All Settings button after making any changes in the Options page. Your settings won't take effect until you save them! After saving, refresh any websites you have open to make sure everything is up-to-date.

That's it! You can now open the WebWire panel on any webpage and start chatting.

🧠 Understanding the Core Concepts

WebWire works like a conversation partner that has read the webpage you're on. Here's how the pieces fit together:

  • The Provider: The company that runs the AI (e.g., OpenAI, Google). This is who you pay and get your API key from.
  • The Model: The specific AI "brain" you want to talk to (e.g., GPT-4o, Claude 3 Sonnet). Each provider offers different models with different strengths.
  • The Samplers: These are the "personality" knobs for the AI. They control how creative, random, or long-winded the model is.
Analogy: Think of it like a sound system. The Provider is the power company (Con Edison), the Model is your amplifier (Marantz, Pioneer), and the Samplers are the bass, treble, and volume knobs.

What's a Tokenizer?

The tokenizer is just a cost and length estimator. It helps WebWire show you an approximation of how much a request will cost before you send it. The AI provider handles the real tokenization on their end.

  • For most modern models (GPT-4, Claude 3, Gemini, Llama 3), cl100k_base is the right choice.
  • When in doubt, leave it on "(Auto-detect)".

Understanding Token Limits & Costs

Max Content Tokens controls how much of a webpage WebWire sends to the AI. This matters because:

Context Window Limits

  • Very small: Groq free tier has a 6,000 token limit
  • Small contexts: Some providers like Featherless limit you to 16,384 tokens
  • Large contexts: Google's Gemini models support up to 1 million tokens
  • Balanced: Most models handle 32K-128K tokens comfortably

Token-Based Pricing

Most providers charge per million tokens, so WebWire trims page content and conversation history to fit your Max Content Tokens setting. Pricing works on two parts:

  • Input tokens: How big your request is (webpage content + conversation history + your message)
  • Output tokens: How long the AI's answer is

Prices below are shown as input/output per million tokens:

  • Premium: OpenAI o1-pro ($150/$600), Claude Opus 4 ($15/$75)
  • Expensive: GPT-4.1 ($2/$8), Claude Sonnet 4 ($3/$15), Gemini 2.5 Pro ($1.25/$10)
  • Moderate: GPT-4.1 Mini ($0.40/$1.60), Claude Haiku 3.5 ($0.25/$1.25), Gemini 2.5 Flash ($0.30/$2.50)
  • Cheap: DeepSeek models ($0.27/$0.27), Qwen models ($0.13-0.30/$0.20-1.20)
  • Free: Many models on OpenRouter (after $10 credit purchase)
  • Fixed price: Featherless ($25/month unlimited)
💡 Cost Tip: Start with Max Content Tokens around 8000-16000 for most tasks. Only increase for very long documents. WebWire will show estimated costs before sending requests.

🎛️ Tuning the AI's Personality (Samplers)

These settings control how the AI generates text. Getting these right is the key to making the AI behave the way you want.

Temperature: The Creativity Knob (0.0 to 2.0)

This is the most important sampler. It controls the randomness of the output.

  • Low (0.1 - 0.3): Precise, predictable, and factual. Good for data extraction, summarization, and technical questions.
  • Medium (0.7 - 0.9): A balance of creativity and coherence. Best for general chat, brainstorming, and balanced analysis. (Recommended starting point)
  • High (1.0+): Wildly creative, poetic, and sometimes nonsensical. Good for artistic writing, but can be less reliable.

Max Response / Content Tokens: The Leash

These control the length of the conversation.

  • Max Response Tokens: Limits how long the AI's answer can be. Keep it lower to save money and get faster responses.
  • Max Content Tokens: Limits how much of the webpage's text is sent to the AI. If a page is huge, this prevents you from sending a massive, expensive request or going over your token limit for a model.

Advanced Knobs (Top P, Top K, Penalties)

For most users, Temperature is enough. These offer finer control for power users. A good starting point is to only set Temperature and leave these blank. If you want to experiment:

  • Top P: Use this instead of Temperature. 0.9 is a good value. It's a different way to control randomness that some people prefer.
  • Penalties: Slightly increase (e.g., to 0.1 or 0.2) if you find the AI repeating itself too much.

✍️ Crafting the AI's Brain (System Prompts)

What is a System Prompt?

The System Prompt is the most powerful setting in WebWire. It's the core set of instructions that the AI reads before every single message you send. It defines the AI's personality, its expertise, its tone, and its rules.

Analogy: If the AI Model is the engine, the System Prompt is the driver. You can tell it to be a cautious driver, a race car driver, or a truck driver—it will fundamentally change how the engine performs.

Examples of Powerful System Prompts:

  • For Editing: You are a skeptical editor from the New York Times. Your goal is to find logical fallacies, weak arguments, and unclear language. Rewrite the user's text to be stronger and more persuasive.
  • For Learning: You are a patient 5th-grade teacher. Explain complex topics using simple analogies and check for my understanding.
  • For Coding: You are a senior software engineer specializing in clean, efficient JavaScript. Provide code solutions that are well-documented and follow best practices.

Power-User Controls

These settings give you fine-grained control over the prompts sent to the AI.

  • Minimal System Message: A shorter, more concise system prompt used when "Minimal Mode" is enabled for a model. Perfect for saving tokens (and money) on simpler models or tasks.
  • User Header & Footer: Text that gets automatically wrapped around every message you send. Useful for consistently adding context, like "My programming language is Python," without having to type it every time.

⚡ Automating Your Workflow (Prompts Library)

One-Click Magic Buttons

The Prompts feature allows you to create reusable "canned prompts" that appear as quick-action buttons in the WebWire chat panel. This is perfect for automating repetitive tasks you perform on web pages.

How It Works:

  1. You define a prompt in the Prompts Manager (accessible from the extension popup).
  2. You give it a name, an icon, and define both the User Prompt (what you're "asking") and a powerful System Prompt (how the AI should behave).
  3. You can configure features, like automatically including the page content or enabling specific tools.
  4. Any prompt you set to "Active" will appear as a button when you open WebWire, ready for one-click execution.
💡 Use Case Example: Create a "Summarize" prompt that automatically includes page content and has a system prompt like "Summarize the following text into five key bullet points for a busy executive." Now you have a one-click summarizer on every page.

🏠 Local Models Setup

Running models locally gives you privacy, control, and potentially lower costs.

⚠️ HTTPS Requirement: Due to Chrome security policies, local model endpoints must use HTTPS. HTTP endpoints will be blocked. You'll need to set up SSL certificates for your local server or use a reverse proxy with HTTPS.

Llama.cpp

Setup: Visit llama.cpp on GitHub

Ollama

github.com/ollama/ollama

The easiest way to run large language models locally.

Required Endpoint: https://localhost:11434/v1 (HTTPS required)

Setup: Visit Ollama on GitHub

General Local Setup

  1. Set Provider to "Local"
  2. Enter your server endpoint in Local Model Endpoint (must start with https://)
  3. Enter the model name as configured in your local server
  4. Choose an appropriate tokenizer (usually "llama" for local models)
  5. Save settings and test
💡 Setting up HTTPS for local servers: Most local model servers run on HTTP by default. You'll need to either configure SSL certificates or use a reverse proxy like nginx or Caddy to add HTTPS support.

🔧 Troubleshooting

Common Issues

API Key Problems:
  • Check that your API key is correctly entered
  • Verify the key has sufficient credits/quota
  • Ensure the key has access to the model you're trying to use
Local Model Issues:
  • Connection refused: Make sure your local server is running
  • Slow responses: Check your hardware resources (CPU/GPU/RAM)
  • Model not found: Verify the model name matches your server configuration
Token Issues:
  • Response too long: Reduce Max Response Tokens
  • Context too large: Reduce Max Content Tokens
  • Expensive usage: Use smaller token limits and enable Minimal Mode

Performance Tips

  • Start with default settings and adjust gradually
  • Use Minimal Mode for token-constrained scenarios
  • Choose appropriate token limits for your use case
  • Test different temperature values for your preferred response style
  • Local models require significant computational resources

🚀 Running Local AI Models with WebWire (Securely!)

To use local AI models with WebWire, your browser requires a secure https:// connection. By default, most local AI servers start with an insecure http:// address.

This guide will walk you through the easiest way to add that secure layer using a free, automatic tool called Caddy.

What is Caddy?

Caddy is a simple web server that can automatically create and manage the necessary SSL/TLS certificates to give your local AI server a secure https:// address. It acts as a "reverse proxy"—a secure entry point that forwards traffic to your insecure local AI server.

Step 1: Install Caddy

Choose your operating system and follow the simple instructions.

🍎

macOS (using Homebrew)

Open the Terminal app.

If you don't have Homebrew, install it first:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Install Caddy:

brew install caddy
🪟

Windows

Method A: Scoop (Recommended)

Open PowerShell and install Scoop:

Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
irm get.scoop.sh | iex

Install Caddy:

scoop install caddy

Method B: Direct Download

Download from Caddy download page

🐧

Linux (Debian/Ubuntu)

Run the following commands:

sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install caddy

Step 2: Create a Caddyfile

Caddyfile 
# WebWire Local AI Server Proxy
#
# This file makes your local AI server available at https://localhost:4430
# It automatically handles HTTPS certificates.

localhost:4430 {
    # This tells Caddy to forward all requests to your local AI server.
    # IMPORTANT: Change "8000" to the port your AI server is running on.
    # Common ports:
    #   - vLLM: 8000
    #   - Llama.cpp: 8080
    #   - Ollama: 11434
    #   - KoboldCpp: 5001
    reverse_proxy localhost:8000
}

Step 3: Run Caddy

  1. Open your Terminal or PowerShell
  2. Navigate to the folder with your Caddyfile
  3. Run: caddy run
Caddy will ask for your administrator/sudo password the first time to install its local certificate authority. This is safe and required for https:// to work.

Step 4: Configure WebWire

  1. Go to the WebWire Options page
  2. Set Provider to Local
  3. In Local Model Endpoint, enter: https://localhost:4430
  4. Enter your local model name (e.g., llama3)
  5. Save your settings
That's it! You can now use your local AI model securely with WebWire.
