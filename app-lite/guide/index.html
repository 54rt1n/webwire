🤖 Model Configuration

Chat Model vs Creative Model

Chat Model (Primary): Used for most interactions, analysis, and general conversation.

Creative Model (Optional): Used for creative tasks when specified. If not configured, the Chat Model is used for everything.

💡 Tip: You can use different models for different purposes - for example, a fast model for chat and a more capable model for creative tasks.

📊 Tokenizer Configuration

What is a Tokenizer?

The tokenizer setting is only used for estimating token counts in WebWire's interface. It doesn't affect how the AI model actually processes your text - that's handled by the provider's servers.

⚠️ Important: The tokenizer is purely for display purposes. Choose one that roughly matches your model for more accurate token count estimates.

Available Tokenizers

  • cl100k_base: Used by GPT-4, GPT-3.5-turbo
  • p50k_base: Used by older GPT-3 models
  • r50k_base: Used by GPT-3 davinci models
  • gpt2: Basic GPT-2 tokenizer
  • claude: Approximation for Claude models
  • llama: For Llama-based models
💡 Quick Guide:
  • GPT-4/3.5 → cl100k_base
  • Claude → claude
  • Llama/Local → llama
  • When in doubt → cl100k_base

🎛️ Sampler Parameters

Core Parameters

Temperature (0.0 - 2.0)

Controls randomness in responses. Lower = more focused, higher = more creative.

  • 0.1-0.3: Very focused, consistent (good for analysis)
  • 0.7-0.9: Balanced (good for conversation)
  • 1.0-1.5: Creative (good for writing)

Max Response Tokens

Maximum length of AI responses. Higher values allow longer responses but cost more.

Max Content Tokens

Maximum tokens from page content sent to the AI. Helps manage context size and costs.

Advanced Parameters

Top P (0.0 - 1.0)

Nucleus sampling - considers only tokens with cumulative probability up to P.

  • 0.9: Good balance (recommended)
  • 0.95: More variety
  • 1.0: Consider all tokens

Min P (0.0 - 1.0)

Minimum probability threshold for token selection. Helps avoid very unlikely tokens.

Top K

Consider only the K most likely tokens. Lower values = more focused.

Penalties (-2.0 - 2.0)

  • Frequency Penalty: Reduces repetition based on how often tokens appear
  • Presence Penalty: Reduces repetition based on whether tokens have appeared

Minimal Mode

Uses a shorter system prompt to save tokens. Useful for models with small context windows or to reduce costs.

🏠 Local Models Setup

Running models locally gives you privacy, control, and potentially lower costs.

🦙 Llama.cpp

High-performance C++ implementation for running LLaMA models locally.

Default Endpoint: http://localhost:8080/v1

Setup: Visit llama.cpp on GitHub

🐉 KoboldCpp

Easy-to-use AI text generation tool with focus on story writing.

Default Endpoint: http://localhost:5001/v1

Setup: Visit KoboldCpp on GitHub

🦌 Ollama

The easiest way to run large language models locally.

Default Endpoint: http://localhost:11434/v1

Setup: Visit Ollama on GitHub

⚡ vLLM

High-throughput and memory-efficient inference engine for large language models.

Default Endpoint: http://localhost:8000/v1

Setup: Visit vLLM on GitHub

General Local Setup

  1. Set Provider to "Local"
  2. Enter your server endpoint in Local Model Endpoint
  3. Enter the model name as configured in your local server
  4. Choose an appropriate tokenizer (usually "llama" for local models)
  5. Save settings and test

🔧 Troubleshooting

Common Issues

API Key Problems:
  • Check that your API key is correctly entered
  • Verify the key has sufficient credits/quota
  • Ensure the key has access to the model you're trying to use
Local Model Issues:
  • Connection refused: Make sure your local server is running
  • Slow responses: Check your hardware resources (CPU/GPU/RAM)
  • Model not found: Verify the model name matches your server configuration
Token Issues:
  • Response too long: Reduce Max Response Tokens
  • Context too large: Reduce Max Content Tokens
  • Expensive usage: Use smaller token limits and enable Minimal Mode

Performance Tips

  • Start with default settings and adjust gradually
  • Use Minimal Mode for token-constrained scenarios
  • Choose appropriate token limits for your use case
  • Test different temperature values for your preferred response style
  • Local models require significant computational resources
